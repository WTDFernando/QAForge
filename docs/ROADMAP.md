# QAForge delivery plan

Each phase ends with working, tested, committed code and a review checkpoint.
Phases 3+ were re-planned after the product brief "Pages and modules / AI agents / Data model / UX rules".
Phase 3 completed the agent framework; the remaining agents ship with the modules they serve (Bug Agent and Failure Analysis in 4, Automation Agent in 5, Report Agent in 6).

| # | Phase | Scope | Status |
|---|---|---|---|
| 1 | **Foundation** | Monorepo, Postgres/Prisma, Better Auth (email + Google/Microsoft SSO), orgs, projects, members, invitations, 7-role RBAC, audit history, app shell, command palette, light/dark, Swagger, Docker Compose, CI | ✅ Done |
| 2 | **Requirements & test cases** | New layout (project switcher, module nav with feature flags, notifications + agent indicator, tablet nav), project dashboard, environments with encrypted secrets, module flags, requirements tree (Epic > Feature > Story, rich text, acceptance criteria, versions, drag & drop, uploads, links), test case repository (suite tree, steps, shared steps, parameterised data, review workflow, versions), list framework (search, filters, saved views, grouping, bulk actions with undo, column chooser, CSV/Excel), traceability links, WCAG 2.2 AA checks | ✅ Done |
| 3 | **AI layer** | `packages/ai` agent framework (versioned prompt files, Zod I/O, tools, evals), Claude adapter + per-org model/key/budget, AgentJob + AiUsage (tokens & cost per call), worker execution with live progress (SSE) in the agent indicator, admins can disable agents. Agents: Requirement Agent (split docs, clarity score, ambiguities, questions), Test Case Writer (techniques, duplicate check via trigram similarity, maps to requirements) with the review queue, Test Case Reviewer, QA Copilot side panel | ✅ Done |
| 4 | **Test runs & bugs** | Runs from suite/filter/release, testers, environment + build, fast execution screen (Pass/Fail/Blocked/Skip shortcuts, evidence, time), "Report bug" pre-filled from a failed step; bug tracker (workflow, severity, Kanban, duplicates suggested, annotated screenshots), Bug Agent, Failure Analysis Agent, notifications | Next |
| 5 | **Automation** | API testing (collections, environments, auth helpers, assertions, chaining, Postman/Bruno/OpenAPI/cURL import), Playwright UI tests with Monaco editor, Automation Agent (test case → page-object test, locator repair with approval), runs on demand / cron / CI webhook in isolated Docker workers, traces/videos, flaky detection, results flow back to runs and draft bugs | |
| 6 | **Releases & reports** | Releases with scope, quality gates, readiness score, named approvers sign-off; reports (execution, Go/No-Go, traceability matrix, bug summary, sprint, automation trend), Report Agent (numbers only from the DB), PDF/DOCX/Excel export, shareable read-only links, branding, scheduled email | |
| 7 | **Platform & integrations** | Jira/GitLab/GitHub/Slack/Teams (incl. requirement import and two-way bug sync), public API tokens, webhooks, MCP server, custom fields, workflows, templates, AI usage dashboard, project-level roles, i18n, OpenTelemetry + Sentry | |
| 8 | **Labs modules** | Performance (k6), security (ZAP baseline, dependency scans, OWASP mapping), accessibility (axe + WCAG 2.2 mapping), visual regression and mobile. Navigation slots and feature flags already exist (Project settings > Modules). | |
